# ТЗ: ИИ-ассистент-архитектор кампании (iter58–iter66)

Статус: **утверждено к работе 08.08.2026.** Идём по шагам; каждый шаг —
отдельная итерация с тестами, ДЕМО-показом и коммитом.

Основание: ассистент из старой волны (`src/apps/assistant.py`) живёт на
ОТДЕЛЬНОЙ вкладке, видит только сводку кампании, не помнит диалог между
запусками, не принимает файлы, не умеет вызывать инструменты и не может
ничего посчитать. Требуется помощник-АРХИТЕКТОР спецификации: он общается с
технологом, понимает, как отразить компонент в программе, и фиксирует
принятые решения компании.

## Канон исполнения (обязателен для каждого шага)

1. **Сначала логика + тест, потом UI** (REBUILD_SPEC §5/§12, `.clinerules`).
   Все хелперы показа — чистые функции (без Streamlit), тестируемые напрямую.
2. **A0.6**: ничего не блокируем молча и не теряем молча. Любой отказ
   инструмента — явный текст с причиной.
3. **ДЕМО на каждом шаге**: `run_assistant_demo.py` печатает то, что увидит
   пользователь (те же чистые хелперы, что пойдут в док). Шаг не считается
   сделанным, если его нечего показать.
4. Тесты: `tests/unit/test_iteration{N}_assistant_*.py`; перед коммитом —
   профильные + регресс (файлы перечислять явно, не glob).

## Инварианты слоя (проверяются тестами)

1. **Сессия привязана к ПРОЕКТУ.** Живёт в
   `project_campaigns/<проект>/assistant/` — переезжает вместе с проектом при
   сохранении/загрузке/удалении. Смена проекта = смена сессии.
2. **Ни один write-инструмент не меняет состояние сам.** `propose_patch`
   только СТЕЙДЖИТ; `apply_patch` требует `human_token`, выданный кнопкой UI,
   и блокируется, если после патча падает `validate_spec` или гейт
   `preflight`.
3. **Тесты — контракт.** Песочница монтирует репозиторий только на чтение;
   правка `tests/` запрещена агенту вообще (защищённый набор — golden-числа
   iter45–57).
4. **Сети в песочнице нет.** Веб — отдельный канал (`:online`), не подпроцесс.
5. **`spec_hash` — единственный источник истины о геометрии.** Патч, который
   двигает отпечаток, помечается явно.
6. **L1 > L2 > L3.** Локальные факты технолога отменяют литературу; конфликт —
   СИГНАЛ в `OPEN_QUESTIONS`, не усреднение.
7. **Полный лог вызовов** пишется в артефакт кампании (`tool_calls.jsonl`) —
   разбор воспроизводим.
8. **Усечение контекста НЕ теряет историю**: в модель уходит хвост диалога,
   на диске остаётся всё, факт усечения виден в контексте явной пометкой.

## Что зафиксировано реализацией iter58 (08.08.2026)

Тесты: `tests/unit/test_iteration58_assistant_session.py`; демо:
`.venv\Scripts\python.exe run_assistant_demo.py`.

1. **Сессия — JSON-native dataclass-контейнер** (`session.py`), без numpy и без
   Streamlit: `Message` / `Attachment` / `Artifact` / `StagedPatch` /
   `ToolCall`. Один формат (`assistant-v1`) читается и пишется
   `to_state`/`from_state` — round-trip побайтно стабилен.
2. **Привязка к проекту — через КАТАЛОГ, а не поле в `campaign.json`**:
   сессия лежит рядом (`assistant/session.json`), поэтому
   `save_campaign`/`load_campaign` не трогаются, а `delete_campaign` (rmtree
   каталога проекта) уносит и переписку — отдельной синхронизации нет.
   Загрузка несуществующей сессии — ПУСТАЯ сессия проекта, не исключение
   (старые проекты грузятся без ошибок, как `sampling_groups` iter31).
3. **Усечение контекста (`context_messages`) НЕ теряет историю**: в модель
   уходит хвост, помещающийся в бюджет, а вместо отрезанного — ОДНО явное
   системное сообщение «опущено N ранних сообщений (полный лог в
   session.json)». Молча урезанный диалог выглядел бы как амнезия ассистента.
4. **Staged-патч несёт поля формата ответа архитектора** (`node`, `field`,
   `from`/`to`, `bound_type` PHYSICAL|CONVENTIONAL, `level` L1|L2|L3,
   `source`, `rationale`, `confidence`, `affects_hash`) — таблица патчей в UI
   собирается без домысливания. Статусы: `staged` → `applied` | `rejected`;
   переход из терминального статуса — явная ошибка.
5. **Дедуп вложений по sha256**: повторное приложение того же файла
   возвращает СУЩЕСТВУЮЩУЮ запись (одно имя — один экземпляр на диске), а не
   плодит копии в контексте.
6. **Журналы — append-only jsonl** (`tool_calls` / `decision_log` /
   `local_facts`): дописывание не переписывает файл целиком, битая строка при
   чтении пропускается с пометкой, а не роняет загрузку проекта.
7. **`views.py` — ОДИН источник таблиц**: демо-скрипт и будущий док печатают
   один и тот же `messages_dataframe` / `attachments_dataframe` /
   `staged_patches_dataframe` / `artifacts_dataframe` / `tool_calls_dataframe`
   и подпись `session_caption`. Разъехавшиеся представления врали бы
   пользователю про одно и то же состояние.

## Что зафиксировано реализацией iter59 (08.08.2026)

Тесты: `tests/unit/test_iteration59_assistant_files.py` (25 шт.); регресс
iter58 — 39; демо: раздел «iter59 · ФАЙЛЫ В СЕССИИ».

1. **Читаем 7 семейств форматов**: текстовые (txt/md/csv/tsv/log/…), json
   (разворачивается с отступами — так модель видит структуру), xlsx/xlsm
   (лист за листом, ячейки табуляцией), docx (абзацы + таблицы), pdf
   (постранично, `pypdf` добавлен в `requirements.txt`). Всё прочее — ЯВНЫЙ
   отказ со списком принимаемых расширений: тихо приложенный бинарник
   превратился бы в мусор в контексте.
2. **PDF-скан без текстового слоя объясняет себя**: текст пуст, но `note`
   говорит «текстового слоя нет (похоже на скан) — нужен OCR». Это прямое
   следствие запрета выдумывать данные паспортов: молча пустое вложение
   читалось бы моделью как «в паспорте этих характеристик нет», и запрет
   работал бы против пользователя.
3. **Дедуп по содержимому, а не по имени**: тот же файл под именем
   «(копия)» возвращает СУЩЕСТВУЮЩУЮ запись и не пишет второй экземпляр на
   диск (демо печатает «записей было 3, стало 3»).
4. **Дайджест vs полный текст**: в контекст идёт `attachment_digest`
   (имя/тип/размер + начало текста), полный — только по запросу
   `attachment_text(start, length)` с флагом `has_more`; при усечении хвост
   ДОЧИТЫВАЕТСЯ с диска, а не теряется.
5. **Кодировки цеха**: utf-8 → cp1251 → utf-8 с заменой. Выгрузки из
   лаборатории часто в cp1251, и «кракозябры» в паспорте — та же потеря
   данных, только незаметная.
6. **Отказ не оставляет мусора**: если извлечение не удалось, файл на диск НЕ
   пишется и записи в сессии не появляется (тест) — иначе в проекте копились
   бы «половинчатые» вложения.
7. **Файлы-сироты показываются, а не удаляются** (`orphan_files`): документ
   мог остаться от очищенной переписки и всё ещё быть нужен.

## Что зафиксировано реализацией iter60 (08.08.2026)

Тесты: `tests/unit/test_iteration60_assistant_llm.py` (20 шт., сеть НЕ нужна —
транспорт подменяется); демо: раздел «iter60 · ХОД АССИСТЕНТА».

1. **Конфиг вынесен из UI** в `assistant/config.py` (ключ, модель, локальный
   `.env`): движок ассистента, инструменты и будущий MCP-сервер не должны
   зависеть от Streamlit-модуля, а ключ — читаться двумя способами. Дефолтная
   модель — `anthropic/claude-sonnet-4.5`.
2. **`:online` — ТУМБЛЕР, а не другая модель** (`online_model`): суффикс
   приписывается ровно один раз и снимается при выключении. Факт веба
   помечается в сообщении сессии (`Message.web`) — иначе утверждение из сети
   неотличимо от утверждения из контекста проекта, а это разные уровни знания
   (L2 против L1/L3).
3. **Цикл `run_tool_loop`**: модель → инструменты → модель, пока не появится
   ответ без вызовов. Возвращает `new_messages` В ПОРЯДКЕ появления (включая
   роль `tool`) — их дописывают в сессию целиком, иначе следующий вопрос
   потеряет контекст уже сделанных вызовов.
4. **Ошибка инструмента уходит МОДЕЛИ** как результат (`ОШИБКА ИНСТРУМЕНТА …`),
   а не рушит ход: отказ `validate_spec` на неверной роли узла — это ПОЛЕЗНЫЙ
   сигнал, из которого модель делает вывод; пользователю нужен разбор, а не
   стектрейс. Битые аргументы (не JSON) обрабатываются так же.
5. **Лимиты объявляются**: `max_iterations` (по умолчанию 8) и общий
   `time_budget_s` (180 с). При исчерпании — честный текст «предел вызовов» /
   «бюджет времени исчерпан», а не молчаливая обрезка. Результат инструмента
   длиннее `MAX_TOOL_RESULT_CHARS` усекается С ПОМЕТКОЙ.
6. **Прогресс наружу** (`on_event` + `progress_caption`): события
   `llm_request` / `tool_start` / `tool_end` / `done` с длительностью. Это
   прямое требование к UI — долгий `run_pytest` не должен выглядеть зависанием;
   сбой обработчика событий не роняет ход (обёрнут).
7. **Транспорт подменяем** (`transport=`) — тесты и демо гоняют весь цикл БЕЗ
   сети; HTTP-ошибки переводятся в человеческие подсказки (401 — ключ, 402 —
   баланс, 404 — имя модели, 429 — частота).

## Что зафиксировано реализацией iter61 (09.08.2026)

Тесты: `tests/unit/test_iteration61_assistant_tools.py` (43 шт., сеть и
собранный проект НЕ нужны); демо: раздел «iter61 · READ-ONLY ИНСТРУМЕНТЫ».

1. **Инструменты закрывают работу ПО ПАМЯТИ.** Любое утверждение о геометрии
   приходит из ядра: `PhrSpec` (роли, `phr_intervals`, `share_bounds_at_total`,
   `spec_hash`), `point_report`, розыгрыш кандидатов, `runner.preflight`, общая
   база точек. Зарегистрировано 13 read-only функций: `get_spec`,
   `explain_node`, `validate_spec`, `simulate_bounds`, `preflight`, `get_runs`,
   `campaign_overview`, `point_report`, `encode_recipe`, `get_local_facts`,
   `get_decisions`, `list_attachments`, `read_attachment`.
2. **Реестр — один источник схемы и исполнения** (`tools/registry.py`):
   описание живёт РЯДОМ с функцией (`@register`), поэтому «модель зовёт то,
   чего нет» невозможно по построению. `tool_specs()` отдаёт JSON-схемы прямо
   в цикл iter60, `dispatch()` их же и исполняет.
3. **Класс доступа проверяется в диспетчере, а не в промпте.** `write` и
   `sandbox` недоступны из readonly-режима, даже если модель узнала имя
   функции из истории (тест с `dummy_write_tool`). Запрет, живущий только в
   тексте промпта, снимается одной удачной формулировкой пользователя.
4. **Golden-числа, а не «вернулся словарь»**: `explain_node('PBNK')`
   воспроизводит немонотонную `hi_φ(T) = min(0.70, 8/T, 1−3/T)` — 0.40 @T=5,
   полка 0.70 @T=10.5, 0.5333 @T=15 (iter45/B1). Потолок ПАРТНЁРА поднимает
   чужой пол: `lo_CPE(15) = 1 − 8/15`. Ответ на «почему диапазон не такой, как
   я ввёл» теперь считается, а не пересказывается.
5. **`simulate_bounds` отличает КЛИН от ТРАПЕЦИИ числами**: corr(UV, DINP)
   = 0.14 при `ABSOLUTE_CAPPED` против 0.89 после патча в `RATIO_TO`. Это
   рабочий аргумент отказа на «привяжи УФ к пластификатору»: клин вшивает
   монотонный prior, который данные уже не опровергнут.
6. **Патч — только dry-run.** `validate_spec` применяет патч к КОПИИ
   (`apply_patch_to_dicts` + конструктор), отдаёт дифф границ и объявляет сдвиг
   `spec_hash`; спека проекта не меняется (тест сверяет hash до/после).
   Отклонение валидацией — это `ok=False` с текстом ошибки, а НЕ исключение:
   для архитектора «так нельзя, потому что…» — ответ по существу.
7. **`normalize_patch` принимает все формы, которые естественно порождает
   модель** (`{node, field, value}`, `{node, set, unset}`, `{"UV": {...}}`,
   списки; спека целиком — узел `__spec__`). Добавление/удаление узлов патчем
   ЗАПРЕЩЕНО с объяснением: это смена схемы проекта, а не правка границы.
8. **`point_report` отдаёт и координату, и phr** (`coord` + `phr`): у
   share-узлов граница живёт в ДОЛЯХ, и сравнение «0.533 против 8» выглядело бы
   нарушением там, где его нет. Активное ограничение помечено явно
   (`active_hi = "max_phr"` — давит складской лимит, а не `share_range`).
9. **Отказы — содержательный текст, уходящий МОДЕЛИ** (A0.6): нет узла — со
   списком имеющихся; нет проекта/спеки — с указанием, где их собрать; вне
   геометрии `encode_recipe` — «признать anchor непредставимым, молча подгонять
   нельзя». Аудит (`dispatcher(on_call=…)`) пишется и на успехе, и на отказе.
10. **`long_running` объявлен в реестре** (`simulate_bounds`, `preflight`) —
    UI берёт признак прогресс-бара из данных, а не из зашитого списка имён.
