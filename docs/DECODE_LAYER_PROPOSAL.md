# Стратегическая заметка: phr/DAG decode-слой (кандидат в REBUILD_SPEC)

Статус: **шаг 1 (iter32, preflight) РЕАЛИЗОВАН** (04.08.2026); остальное —
предложение, не в работе. Зафиксировано после iter31 (групповой
стратифицированный сэмплер) по итогам внешнего архитектурного обсуждения
(сессия 04.08.2026). Решение об этапах A/B — после эксплуатации preflight.


## Контекст и мотивация

Рецептуры типа PVC-компаундов нормируются на смолу = 100 phr: суммарная
масса ПЛАВАЕТ, доли считаются как `w_i = p_i / (100 + Σp_j)` (проективное
преобразование с непостоянным якобианом). Текущий вход через
`parts_ranges_to_fraction_bounds` даёт лишь ТЕСНЫЙ БОКС в пространстве
долей — структура parts-области (независимость групп в phr) теряется.

Кроме того, в текущей схеме невыразимы:
- групповое ограничение `Σ_group ∈ [L, U]` (iter31 закрыл только
  ПОКРЫТИЕ оси суммы группы сэмплером, не ограничение);
- относительная дозировка `ratio_to` к произвольному узлу (например,
  «SBM = 0.02…0.09 × Σ стабилизатора» — reference НЕ родительская
  группа, поэтому нужен DAG, а не дерево).

## Суть предложения (двухслойная параметризация)

    z (design coords) --decode--> p (phr) --batch--> m (граммы)

- **z** — тотали групп + доли внутри групп + ratio-коэффициенты
  (физически осмысленные оси). Генератор плана / GP / оптимизатор
  работают в z.
- **p** — phr по компонентам: cost-модель, ограничения по сырью, отчёты.
- **m** — навеска с учётом разрешения весов (quantize + правило премикса
  `δ_phr / (U−L) > 0.05 ⇒ премикс`).

Ключевые элементы (из внешнего обсуждения, проверены на здравость):
1. Spec-конфиг → DAG узлов, 4 режима координат: `absolute` | `share_of` |
   `ratio_to` (к произвольному узлу) | `fixed`; топосорт + детекция циклов.
2. Статическая валидация интервальной арифметикой ДО сэмплинга
   (пустые пересечения — ошибка конфига, не sample-time).
3. Sobol/LHS в z-кубе + **conditional narrowing** (без rejection);
   доли групп из k≥3 членов — существующий `SimplexRegion`.
   Мера: uniform-MARGINAL по физически значимым осям (осознанный выбор,
   тот же, что задокументирован в iter31 `random_points(groups=…)`).
4. `decode(z)→p` и `encode(p)→z` (roundtrip-тест) — anchors/исторические
   рецепты задаются в phr.
5. Preflight-гейты плана: rank / cond / VIF / max|corr| / blind-direction —
   ловят вырожденный план ДО измерений. **Поправка iter32 (эмпирика):
   абсолютные пороги cond<30 / VIF<5 / |corr|<0.30 в ДОЛЯХ Шеффе-квадратик
   неприменимы** (хороший план n=24 при q=6: cond≈2000, VIF≈1e5, corr≈0.9 —
   Σx=1 и узкий L/U-бокс наводят структурную коллинеарность). Гейты сделаны
   ОТНОСИТЕЛЬНЫМИ к reference-пулу той же области; абсолютные пороги
   осмысленны только в z-пространстве (этап A/B).

6. Augmentation (maximin от existing), версионирование spec (хеш),
   индикатор кампании в модели.

## Сверка с кодовой базой (что внешняя сессия не видела)

- Канон Σx=1 прошит насквозь: `ProjectSchema` (≤1 MIXTURE-блок),
  `DataPoint.validate`, термы Шеффе (`n_scheffe_params`, quadratic-mean
  GP), M3-скрининг, миграция точек, campaign_ui, cost-функции. Полная
  «модель в z» — перестройка масштаба раздела REBUILD_SPEC, не итерации.
- Проект обслуживает и НАСТОЯЩИЕ смеси (Σ=1 — физика). Decode-слой
  обязан быть ДОПОЛНИТЕЛЬНЫМ режимом входа, а не заменой симплекса.
- Мост для поэтапного внедрения: генератор кандидатов — ПОЛИТИКА
  (любое распределение допустимых точек легально). Decode-слой может
  родиться как САМПЛЕР-ПЛАГИН: сэмплим в z (parts/phr), декодируем в
  доли (Σ=1 автоматически), скармливаем как кандидатов — схема/GP/
  миграция/UI нетронуты. Полная z-модель (RSM вместо Шеффе, GP в z,
  encode истории) — отдельное решение, когда упрёмся в p_quad=21 /
  порог n≥2p=42 при q=6.
- Refine-оптимизатор (`optimize_desirability`) уже доходит до краёв
  области — проблема покрытия касалась пулов кандидатов (закрыта iter31).
